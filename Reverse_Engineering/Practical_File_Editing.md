# Практическое редактирование файлов X3TC — первый разбор

## Цель
На реальном XML-файле понять, какие значения являются текстом, переменными, числовыми литералами, индексами конфигурации и текстовыми ID. Это первичное наблюдение, а не полная спецификация формата.

## Исследованный образец
- Файл: `plugin.gz.mars.config_modified(1).xml`
- Размер локального образца: 959,153 байта.
- XML успешно прочитан стандартным XML-парсером.
- Корневой элемент: `script`.
- Обнаружены элементы `name`, `version`, `engineversion`, `description`, `arguments`, `sourcetext`, `codearray`.

## Что видно в `sourcetext`
В образце содержится 2246 элементов `line`. Каждый элемент имеет атрибуты `linenr` и `indent`. Внутри строк встречаются вложенные токены `var`, `text`, `comment` и другие элементы.

Примеры исходного текста (NBSP в строках визуально отображается как пробел):
- Строка 003: присваивание переменной `$MARS.Config` результатом команды чтения глобальной переменной с именем `GZ.MARS.CONFIG`.
- Строка 004: `skip if $MARS.Config`.
- Строка 007: `$PageID = $MARS.Config[2]`.
- Строка 010: `$Dummy1 = $MARS.Config[192]`.
- Строки 013–015: переменные `$Cfg.On`, `$Cfg.Off`, `$Cfg.Auto` присваиваются результатами команд чтения текста с ID 2405, 2406, 2407 соответственно.
- Строки 021–027: переменным с именами `$VarName.*` присваиваются элементы `$MARS.Config` с индексами 129, 130, 131, 127, 132, 118 и 159.

Это наблюдения о том, что записано в XML; они не объясняют семантику каждого индекса.

## Что видно в `codearray`
- Элемент `codearray` присутствует.
- В нём обнаружен один непосредственный дочерний элемент `sval` типа `array`, с атрибутом `size="10"`.
- У этого массива фактически 10 дочерних `sval`.
- Среди первых значений присутствуют имя скрипта, целое `44`, строка описания `MARS - Menu`, два целых нуля и вложенные массивы с заявленными размерами 78, 1788, 2 и 674, а также завершающее целое 0.

Наличие обоих разделов не доказывает, какой раздел X-Studio использует при загрузке и какой пересоздаёт при сохранении. Не изменять только один из разделов в рабочем файле, пока не проведён тест на копии.

## Как различать значения перед изменением
1. **Текст/имя/описание** — строковые значения, например `description` или строковые токены в `sourcetext`. Перед заменой проверить, не является ли строка идентификатором, используемым другими скриптами.
2. **Числовой литерал** — число непосредственно в выражении (например, `1000` в строках, где оно встречается). Изменять только после определения назначения числа и диапазона.
3. **Индекс массива/конфигурации** — запись вида `$MARS.Config[185]`. Число в квадратных скобках является индексом, а не обязательно значением настройки. Не менять индекс без выяснения схемы конфигурации.
4. **Text ID** — числа после `id=` в командах чтения текста. Это ссылка на локализационный текст; изменение ID может вывести другой текст или привести к отсутствующей строке. Сначала сверять с соответствующим файлом языковых текстов.
5. **ID страницы** — значения после `page=` или переменные, подставляемые в параметр page. Не считать их обычными числовыми настройками.

## Безопасный цикл редактирования
1. Создать резервную копию оригинала.
2. Выбрать одну конкретную строку/значение и записать исходное состояние.
3. Проверить назначение значения по контексту, другим скриптам и языковому файлу.
4. Изменить только выбранное значение в копии.
5. Проверить XML-парсером, структуру, атрибуты и количество элементов.
6. Сравнить diff, убедиться, что изменена только ожидаемая область.
7. Открыть копию в X-Studio и сохранить её — только так можно проверить поведение редактора при загрузке/сохранении.
8. Проверить изменённый скрипт в игре. Без этих запусков подтверждается только структурная корректность, не функциональность.

## Пока не подтверждено
- Как X-Studio 1.08 трактует `sourcetext` и `codearray` при загрузке.
- Может ли редактор восстановить один раздел из другого или сохраняет оба без синхронизации.
- Полная карта индексов `$MARS.Config[n]` и допустимые диапазоны значений.
- Семантика всех числовых литералов, ID страниц и ID текста.
- Поведение игры после ручного изменения значений.

## Следующий шаг
Построить карту конкретных настроек `$MARS.Config[n]`: собрать места чтения и записи каждого индекса, связать их с пунктами меню/текстами и определить проверяемые диапазоны. Не назначать названия параметрам, пока связь не подтверждена кодом и/или тестом.
